## 一、执行前必读

### 1.1 硬规则

- **严禁用模拟器代替真机验收。** 模拟器可用于开发自测，但其结果**不得**写入本计划的验收结论，也不得作为证据提交。
- **设备资源保护守则优先。** 所有重任务串行执行：构建、测试、录屏、ADB 操作不得并行。上一项确认资源回落后再开始下一项。
- 所有沟通、记录、结论使用简体中文。
- 证据统一存 `test-evidence/`，命名带用途与日期。

### 1.2 强烈建议：先修阻塞项再开工

**联网组（第四阶段）当前 100% 会失败**，原因见 `发布前最终QA门控清单.md` BUG-001：打包 App 内 WebSocket 地址被解析为 `wss://localhost:3001/ws`，指向手机自身。

若不先修复就召集四台设备和四个人，**整场测试会在第一步"创建房间"卡死，全部空跑**。

建议顺序：

```
修复 BUG-001
   ↓
阶段一 环境准备 → 阶段二 Android → 阶段三 iOS → 阶段四 联网 → 阶段五 压测
```

若暂不修复，可先执行**阶段一、二、三、五**（单机链路不依赖服务器），跳过阶段四，并在结论中明确标注"联网组未执行，原因 BUG-001"。

## 二、哪些项必须人工真机完成（不可自动化）

| 项目 | 为什么不能自动化 |
|---|---|
| 触屏手感与误触 | 需要真实手指尺寸与触摸采样，仿真点击无法反映热区是否够大 |
| 横屏物理旋转 | 需真实重力感应与系统旋转策略，浏览器改视口尺寸不等价 |
| 刘海屏 / 挖孔 / 手势条安全区 | 各厂商实现差异大，只有真机能暴露 |
| 冷启动白屏与启动页时序 | 依赖真实 WebView 初始化与磁盘 IO 速度 |
| 四台设备真实并发同步 | 需要真实网络栈、真实并发时序，单机多开不等价 |
| 断线重连 | 需真实断网（飞行模式 / 关 Wi-Fi），代码模拟不等价 |
| 数小时内存曲线 | 需真实内存回收压力与系统调度 |
| 电量、发热、后台被杀 | 只有真机存在 |
| iOS 签名与安装 | 必须 Mac + Xcode + 真实 Apple ID |

**可自动化、已完成、无需真机重复的项**：规则引擎正确性、100 盘机器人对局稳定性、构建产物、体积门槛。这些已在 2026-08-07 由 QA 实跑复核通过，真机阶段不必重复，只需在真机上抽验一局确认规则表现一致。

## 八、阶段五：数小时持续运行内存压力测试

### 8.1 执行方式

在 Android 真机上运行 App，连续进行单机对局（可利用自动推进），持续 **不少于 4 小时**。

**串行提醒**：压测期间开发机不要跑构建、测试或模拟器，避免干扰与违反资源保护守则。

### 8.2 采样方法

每 15 分钟采样一次内存，共约 16 个点：

```
adb shell dumpsys meminfo com.zhijianmahjong.game | findstr TOTAL
```

记录到 CSV：`test-evidence/memory-samples-<日期>.csv`，字段：时间戳、已运行分钟数、TOTAL PSS(KB)、已完成局数、界面是否响应。

同时后台抓日志：

```
adb logcat -c
adb logcat > test-evidence/android-logcat-longrun-<日期>.txt
```

### 8.3 验收标准

| 编号 | 检查项 | 通过标准 |
|---|---|---|
| M-1 | 持续时长 | ≥ 4 小时不中断 |
| M-2 | 无崩溃 | 日志无 FATAL EXCEPTION、无 ANR、进程未被系统杀死 |
| M-3 | 无内存泄漏 | 内存曲线在多局后有回落，不呈单调上升；末点较首点增幅 < 20% |
| M-4 | 无卡死 | 首 / 中 / 末各录一段 30 秒，界面持续响应 |
| M-5 | 定时器不累积 | 长跑后与初始状态对比，定时器与监听器数量稳定 |

### 8.4 重点观察对象

代码审计已定位以下风险点，若 M-3 不达标优先从这些位置排查：

| 位置 | 风险 |
|---|---|
| `src/app/main.js:1668` | 1 秒 `setInterval` 更新系统时间，**永不清除** |
| `src/app/main.js:311` | `BACKGROUND_MUSIC_TIMER` 每 1.4 秒触发一次音频合成 |
| `src/app/main.js:429` | `USER_REACTION_TIMER` 倒计时定时器 |
| 全局 | `setTimeout` 16 处 vs `clearTimeout` 仅 2 处 |
| 全局 | `addEventListener` 45 处 vs `removeEventListener` 0 处 |
| `src/app/main.js:586` | 每次渲染重建手牌 DOM 并重新绑定点击监听 |

> 已排除项：`ROOM_SOCKET` 在 1540 / 1582 / 1625 / 1644 均正确调用了 `close()`，**不存在 socket 句柄泄漏**，无需在此方向排查。

### 8.5 补充建议

音频路径值得单独留意：`playGameSound` 每次调用都新建 `OscillatorNode` 与 `GainNode`（`src/app/main.js:294-303`），背景音乐每 1.4 秒触发一次。4 小时约 10000 次节点创建。Web Audio 节点在停止后应被自动回收，但若 M-3 曲线异常，建议做一组对照：**关闭音效跑 1 小时 vs 开启音效跑 1 小时**，比较内存曲线差异，即可快速定位是否与音频相关。

## 九、风险与回滚

### 9.1 测试执行风险

| 风险 | 可能性 | 影响 | 应对 |
|---|---|---|---|
| BUG-001 未修就开测联网组 | 高 | 四台设备与人力全部空跑 | 阶段四前置检查 4-0-1 强制拦截 |
| 路由器 AP 隔离导致设备互不可见 | 中 | 联网组无法开始 | 前置 4-0-2 / 4-0-4 先验证连通性 |
| 防火墙拦截 3001 | 中 | 手机连不上服务器 | 前置 1-7 先验证 |
| 只有 1–2 台 Android | 中 | 四台条件不满足 | 降级执行并如实标注，**不得**用模拟器凑数 |
| 无 Mac | 中 | iOS 组无法执行 | 明确标注 iOS 未验收，不得以浏览器仿真代替 |
| 压测期间并行跑构建 | 中 | 违反资源守则，数据失真 | 压测期间开发机不做其他重任务 |
| 录屏占用资源影响帧率判断 | 低 | 帧率数据偏低 | 分段录制，不全程录 |

### 9.2 回滚方案

| 场景 | 回滚动作 |
|---|---|
| 新 APK 真机闪退 | 卸载新包，回退到上一个可用 APK（保留 `app-debug.apk` 副本并改名带日期归档） |
| 修复 BUG-001 引入新问题 | Git 回退该次提交，重跑 `node --test tests/*.test.js` 确认 108/108 恢复 |
| 服务端改动导致房间异常 | 回退 `server/` 相关提交，重跑 `roomService.test.js` 与 `webSocketServer.test.js` |
| 真机数据异常 | 卸载重装清数据；账号数据本就纯内存（BUG-003），重启服务即清空 |

**归档要求**：每次真机测试前，把当前 APK 复制一份为 `app-debug-<日期>.apk` 留底，避免新包有问题时无可用版本回退。
